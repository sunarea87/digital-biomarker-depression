# 우울증 디지털 바이오마커 분석 코드

손목 착용형 웨어러블(Fitbit)에서 나온 수면과 심박변이와 활동량 자료로
우울장애 환자의 6주 뒤 상태를 판별하고, 어떤 지표가 얼마나 기여했는지를 수치로 내는 코드임.

식약처 과제 24202미래기201, 가천대학교 의공학교실, IRB GCIRB2024-093.

읽는 목적별 바로가기임.

| 알고 싶은 것 | 볼 곳 |
|---|---|
| 바이오마커를 어떻게 가공하는가 | 3장 |
| 중요도를 재는 코드가 무엇인가 | 4장 |
| 그 결과를 어떻게 읽는가 | 5장 |
| 올려둔 샘플 데이터가 무엇인가 | 6장 |
| 당장 돌려보고 싶다 | 1장 |

## 1. 빠른 시작

샘플 데이터로 5분 안에 전체 흐름을 확인할 수 있음.

```
pip install -r requirements.txt

python - <<'EOF'
import biomarker as bm
w, l = bm.load_cohort("샘플데이터/비정형_120명")
idx = l.index[l["HAMD_v4"].notna()]
y = (l.loc[idx, "HAMD_v4"] >= 14).astype(int).values
X = bm.representation(w, "poly").loc[idx]
yy, pp = bm.oof_predict(X.values, y, "RF", "record", n_repeats=3)
print(bm.full_metrics(yy, pp))
EOF
```

전체 실험을 돌리려면 `config.json` 의 `out_dir` 을 샘플 폴더로 바꾼 뒤 아래를 실행함.

```
python step2_analyze.py      실험 전부, 결과표 CSV 생성
python step3_figures.py      결과표로 그림 생성
```

`step1_preprocess.py` 는 Fitbit 원본 폴더를 읽는 단계임.
원본은 개인정보라 저장소에 없음. 새 대상자가 추가될 때만 필요함.

## 2. 파일 구성

파이썬 파일은 네 개임. 셋은 `biomarker.py` 에서 함수를 가져다 씀.

| 파일 | 역할 | 직접 실행 |
|---|---|---|
| `biomarker.py` | 함수 전부. 파싱, 특징 생성, 모형, 지표, 중요도, 그림 | 안 함 |
| `step1_preprocess.py` | Fitbit 원자료를 분석용 표로 변환 | 원본 있을 때만 |
| `step2_analyze.py` | 실험 전부 실행, 결과표 생성 | 함 |
| `step3_figures.py` | 결과표로 그림 생성 | 함 |

`biomarker.py` 맨 위 주석에 함수 찾아보기가 들어 있음.

이 저장소에 없는 것이 둘 있음.

- `결과/` 폴더. 실제 자료로 돌린 결과표와 논문용 그림이 들어 있음. 기관 내부에만 둠
- `config.json`. 원본 자료 경로가 적혀 있음. `config.example.json` 을 복사해 쓸 것

5장에 실린 수치는 그 `결과/` 폴더에서 가져온 참고값임. 해석 방법을 익히는 데 쓸 것.

## 3. 바이오마커를 어떻게 다루는가

이 장이 이 저장소의 핵심임. 원시 신호에서 모델 입력까지 다섯 단계를 거침.

[ 3-1. 전체 흐름 ]

```
Fitbit 내보내기 폴더
   수면 JSON / 심박변이 CSV 2종 / 활동 JSON
        |
        |  1단계  관찰 창 자르기          biomarker.visit_windows
        v
   방문마다 7일치 구간
        |
        |  2단계  하루 단위로 집계        read_sleep_days / read_hrv_days / read_activity_days
        v
   daily_long.csv        1행 = 1대상자 x 1날짜 x 16지표
        |
        |  3단계  품질 기준 적용          window_coverage / select_cohort
        v
   영역별 3일 이상 확보된 창만 남김
        |
        |  4단계  창 단위 요약            visit_summary
        v
   visit_wide.csv        1행 = 1대상자, 열 = 지표__방문
        |
        |  5단계  시간 정보 표현          representation / polynomial_basis / trajectory_summary
        v
   모델 입력 행렬
```

[ 3-2. 1단계 관찰 창 ]

방문마다 7일치를 잘라 씀. 함수는 `biomarker.visit_windows` 임.

| 방문 | 주차 | 창 |
|---|---|---|
| v1 | 0주 | 첫 방문일부터 7일 |
| v2 | 2주 | 첫 방문일 기준 14일째부터 7일 |
| v3 | 4주 | 첫 방문일 기준 28일째부터 7일 |
| v4 | 6주 | 마지막 방문일까지의 직전 7일 |

6주만 거꾸로 셈. 실제 방문 간격이 계획된 42일에서 벗어난 대상자가 많았고,
앞에서부터 세면 관찰 창이 6주 임상 평가 시점과 어긋나기 때문임.

[ 3-3. 2단계 하루 단위 집계 ]

지표는 16종임. 영역별 담당 함수가 다름.

| 영역 | 지표 | 열 이름 | 담당 함수 |
|---|---|---|---|
| 수면 6종 | 깊은 수면, 얕은 수면, 렘 수면, 수면 중 각성, 수면 효율, 침대 체류시간 | `SQ_*` | `read_sleep_days` |
| 심박변이 5종 | RMSSD, 비렘수면 심박수, 엔트로피, 저주파수 LF, 고주파수 HF | `HRV_*` | `read_hrv_days` |
| 활동 5종 | 총 활동 시간, 평일/주말 이동 거리, 평일/주말 소모 칼로리 | `ACT_*` | `read_activity_days` |

같은 날짜에 세션이 여러 개면 세션 평균을 씀.
이동 거리와 소모 칼로리만 평일과 주말로 나눠 따로 평균함. 사회활동 패턴이 다르기 때문임.
강도별 활동 시간은 서로 상관이 높아 총 활동 시간 하나로 합쳤음.

렘수면 잠복기는 후보에서 제외했음.
첫 렘수면 출현 시각이 확인되는 경우에만 산출되어 결측이 아주 많고,
아래 3일 기준을 함께 적용하면 분석 가능한 대상자가 크게 줄기 때문임.

[ 3-4. 3단계 품질 기준 ]

한 관찰 창에서 수면과 심박변이와 활동 각 영역별로 3일 이상 값이 있어야 그 창을 인정함.
기준은 `biomarker.MIN_DAYS_PER_WINDOW` 에 있음.
기준 미달 창은 버리고 추정값으로 메우지 않음.
미착용으로 빈 날을 채우면 실제로 움직이지 않은 날과 구분되지 않아 활동량 해석이 왜곡되기 때문임.

[ 3-5. 4단계 창 단위 요약 ]

`biomarker.visit_summary` 가 창 안의 일별 값을 평균해 `지표__방문` 형태의 열로 만듦.
결과는 1행 = 1대상자, 16지표 곱하기 방문 수 열임.

[ 3-6. 5단계 시간 정보 표현 ]

`biomarker.representation(wide, kind)` 로 고름. 여섯 가지가 있음.

| kind | 구성 | 입력 변수 수 |
|---|---|---|
| `raw2` | 0주와 6주 원값 | 32 |
| `raw4` | 네 시점 원값 | 64 |
| `traj` | 네 시점 원값 + 지표별 선형 기울기와 총변화 | 96 |
| `poly` | 직교다항 P0와 P1 | 32 |
| (직접 호출) | `polynomial_basis(wide, ("P0","P1","P2"))` | 48 |
| (직접 호출) | `polynomial_basis(wide, ("P0","P1","P2","P3"))` | 64 |

직교 다항 대비를 쓰는 이유임.
네 시점 값을 그대로 붙이면 지표 하나당 변수가 4개 생기고 인접 시점 상관이 높아 모형이 불안정해짐.
등간격 네 시점의 가중치는 `biomarker.POLY_CONTRAST` 에 있음.

| 성분 | 가중치 | 뜻 |
|---|---|---|
| P0 | 1, 1, 1, 1 | 6주 전체 평균 수준 |
| P1 | -3, -1, 1, 3 | 선형 변화의 방향과 속도 |
| P2 | 1, -1, -1, 1 | 중간에 꺾이는 U자형 |
| P3 | -1, 3, -3, 1 | 등락이 한 번 더 반복 |

계수는 값 벡터와 가중치 벡터의 내적을 가중치 제곱합으로 나눠 구함.
네 벡터가 서로 직교하므로 성분 간 상관이 0임.
따라서 평균 수준이 낮아서 위험한 것인지, 기간 중 감소해서 위험한 것인지를 분리해 해석할 수 있음.
이것이 원값을 그대로 쓰는 방식과 결정적으로 다른 점임.

[ 3-7. 분석 단위 두 가지 ]

같은 자료를 단위를 달리해 두 번 봄. 결과 해석이 갈리므로 반드시 구분해야 함.

| 구분 | 정형 | 비정형 |
|---|---|---|
| 한 표본의 정체 | 방문 하나 | 대상자 한 명 |
| 표본 수 | 146명 곱하기 2방문 = 292 | 141명 = 141 |
| 입력 | 그 방문 창의 16지표 | 네 시점을 요약한 벡터 |
| 같은 대상자 중복 | 있음 | 없음 |
| 관련 함수 | `to_visit_rows` | `representation` |

정형은 같은 대상자의 두 방문이 학습과 평가로 갈릴 수 있음.
그래서 방문 단위 분할과 대상자 단위 분할을 모두 산출해 차이까지 보고함.
차이를 재는 함수는 `biomarker.record_vs_subject` 임.

## 4. 어떤 바이오마커가 얼마나 중요한지 재는 코드

[ 4-1. 담당 함수 ]

`biomarker.shap_importance(X, y, feature_names, model, seed, n_repeats)` 하나임.

동작은 다음과 같음.

- 교차검증 겹마다 모형을 학습함
- 그 겹의 평가 부분에서만 SHAP 값을 수집함
- 절댓값을 평균해 지표별 기여도를 냄
- 기여도가 큰 순으로 정렬한 DataFrame 을 돌려줌. 열은 `특징` 과 `SHAP` 임

평가 부분에서만 모으는 것이 중요함.
학습에 쓰인 표본의 기여도를 섞으면 중요도가 낙관적으로 나옴.

[ 4-2. 어디서 호출되는가 ]

`step2_analyze.py` 안 두 곳임.

| 위치 | 입력 | 설명 대상 모형 | 출력 파일 |
|---|---|---|---|
| `run_structured` 끝부분 | 방문 단위 16지표 원값 | XGB | `결과/structured_shap.csv` |
| `run_longitudinal` 끝부분 | 직교다항 P0와 P1 (32성분) | RF | `결과/longitudinal_shap.csv` |

그림으로 보려면 `step3_figures.py` 를 돌림.

| 그림 | 내용 |
|---|---|
| `s_shap_severity` / `s_shap_suicide` / `s_shap_anxiety` | 표현형별 16지표 기여도 가로 막대 |
| `s_rank_heatmap` | 세 표현형의 순위를 한 장에 비교 |
| `l_shap_severity` / `l_shap_suicide` / `l_shap_anxiety` | 궤적 성분별 기여도 |

[ 4-3. 두 출력 파일의 차이 ]

`structured_shap.csv` 는 순위를 담음. 1이 가장 중요함. 행은 지표 16개, 열은 표현형 3개임.
`longitudinal_shap.csv` 는 SHAP 값 자체를 담음. 행은 32성분(16지표 곱하기 평균/기울기)임.
성분 이름은 `평균 · 총 활동 시간` 처럼 붙음.

## 5. 결과를 어떻게 해석하는가

[ 5-1. SHAP 값이 무엇인지 ]

이 코드가 내는 값은 mean(|SHAP value|) 임. 기여의 크기만 나타냄.

지켜야 할 규칙 네 가지임.

- 크기만 있고 방향은 없음. 값이 크다는 것은 그 지표가 예측을 많이 흔들었다는 뜻이지 위험을 높인다는 뜻이 아님
- 절대값을 다른 표와 비교하면 안 됨. 모형과 표현 방식이 다르면 눈금이 달라짐
- 같은 표 안에서 순위와 상대 크기로만 읽어야 함
- 상관관계이지 인과가 아님

[ 5-2. 방향은 따로 확인해야 함 ]

SHAP 크기만으로는 높을수록 위험인지 낮을수록 위험인지 알 수 없음.
양성군과 음성군의 중앙값을 비교해 따로 확인해야 함.

```
from scipy import stats
a = m.loc[y == 1, "ACT_distances_weekday"].dropna()   # 양성군
b = m.loc[y == 0, "ACT_distances_weekday"].dropna()   # 음성군
print(a.median(), b.median(), stats.mannwhitneyu(a, b))
```

실제 자료에서 확인한 방향임.

| 표현형 | 지표 | 양성군 중앙값 | 음성군 중앙값 | 방향 | p |
|---|---|---|---|---|---|
| 중증도 | 평일 이동 거리 | 664.4 | 934.4 | 낮을수록 위험 | 0.0000 |
| 중증도 | 총 활동 시간 | 196.6 | 278.7 | 낮을수록 위험 | 0.0000 |
| 중증도 | 깊은 수면 시간 | 45.2 | 55.5 | 낮을수록 위험 | 0.0001 |
| 자살사고 | 수면 효율 | 92.7 | 93.8 | 낮을수록 위험 | 0.0002 |
| 불안 | 비렘수면 심박수 | 66.2 | 60.7 | 높을수록 위험 | 0.0000 |

비렘수면 심박수만 방향이 반대임. 값이 높을수록 불안 동반 위험이 높음.
나머지는 전부 값이 낮을수록 위험이 높음.

[ 5-3. 실제 자료에서 나온 순위 ]

`결과/structured_shap.csv` 의 내용임. 숫자가 작을수록 기여가 큼.

| 지표 | 중증도 | 자살사고 | 불안 |
|---|---|---|---|
| 평일 이동 거리 | 1 | 3 | 1 |
| 총 활동 시간 | 2 | 1 | 4 |
| 깊은 수면 시간 | 3 | 2 | 3 |
| 주말 이동 거리 | 4 | 4 | 7 |
| RMSSD | 5 | 12 | 14 |
| 얕은 수면 시간 | 6 | 9 | 11 |
| 렘 수면 시간 | 7 | 13 | 8 |
| 엔트로피 | 8 | 14 | 9 |
| 주말 소모 칼로리 | 9 | 6 | 15 |
| 수면 효율 | 10 | 5 | 5 |
| 저주파수 LF | 11 | 8 | 6 |
| 평일 소모 칼로리 | 12 | 15 | 13 |
| 침대 체류시간 | 13 | 11 | 10 |
| 고주파수 HF | 14 | 16 | 12 |
| 비렘수면 심박수 | 15 | 7 | 2 |
| 수면 중 각성 시간 | 16 | 10 | 16 |

읽어야 할 결론 네 가지임.

- 공통 바이오마커는 평일 이동 거리, 총 활동 시간, 깊은 수면 시간임. 세 표현형 모두 4위 안에 듦
- 우울 상태의 공통 신호는 움직임 감소와 깊은 수면 감소임
- 자율신경 지표는 공통 바이오마커가 아님. 심박변이 다섯 개 중 상위권은 불안의 비렘수면 심박수뿐임
- 표현형 특이 지표가 둘 있음. 자살사고의 수면 효율(5위, 중증도에서는 10위)과 불안의 비렘수면 심박수(2위, 중증도에서는 15위)임

[ 5-4. 궤적 성분 해석 ]

`결과/longitudinal_shap.csv` 의 상위임.

| 표현형 | 1위 | 2위 | 3위 | 4위 |
|---|---|---|---|---|
| 중증도 | 평균 총 활동 시간 | 평균 주말 이동 거리 | 평균 평일 이동 거리 | 평균 엔트로피 |
| 자살사고 | 평균 총 활동 시간 | 평균 주말 이동 거리 | 평균 평일 이동 거리 | 평균 수면 효율 |
| 불안 | 평균 평일 이동 거리 | 평균 총 활동 시간 | 평균 주말 이동 거리 | 평균 비렘수면 심박수 |

세 표현형 모두 상위 네 자리가 전부 평균 성분(P0)임.
기울기 성분(P1) 중 가장 높은 것은 자살사고의 수면 중 각성 시간 6위임.
즉 변화의 방향은 평균 수준을 이기지 못함.

그런데도 궤적 표현이 원값 2시점을 이김.
네 시점을 평균 내면서 하루 단위 흔들림이 걸러지기 때문임.
이득의 출처는 추세 자체가 아니라 측정 안정화 쪽임. 이 해석을 빠뜨리면 결과를 잘못 읽게 됨.

[ 5-5. 판별 성능 참고값 ]

`결과/full_metrics.csv` 가 유일한 출처임. 문서에 옮겨 적지 말고 이 파일을 읽어 쓸 것.

| 표현형 | 정형 대상자 단위 | 비정형 궤적 | 차이 |
|---|---|---|---|
| 우울 중증도 | 81.3 | 87.6 | 6.3 |
| 자살사고 | 74.1 | 83.7 | 9.6 |
| 불안 동반 | 76.3 | 82.1 | 5.8 |

임상 적용 시 기대 성능은 대상자 단위 쪽임.
방문 단위 값은 같은 대상자의 두 방문이 학습과 평가로 갈리면서 3에서 5포인트 높게 나옴.

## 6. 샘플 데이터

[ 6-1. 무엇인가 ]

`샘플데이터/` 안의 두 폴더임. 전부 컴퓨터가 지어낸 가짜 환자 120명임.
실제 환자 기록은 한 줄도 들어 있지 않음.

| 폴더 | 파일 | 내용 |
|---|---|---|
| `정형_120명` | `visit_wide.csv` | 120행 곱하기 32열 (16지표 곱하기 v1, v4) |
| `정형_120명` | `labels.csv` | 120행 곱하기 9열 (임상 점수) |
| `비정형_120명` | `visit_wide.csv` | 120행 곱하기 64열 (16지표 곱하기 v1~v4) |
| `비정형_120명` | `labels.csv` | 위와 동일 |

`labels.csv` 의 열은 다음과 같음.

| 열 | 뜻 |
|---|---|
| `grp` | 1 = 우울군, 0 = 건강 대조군 |
| `HAMD_v1` / `HAMD_v4` | 0주 / 6주 해밀턴 우울척도 총점 |
| `SUI_v1` / `SUI_v4` | 0주 / 6주 HAMD 제3문항(자살) 점수 |
| `BAI_v1` / `BAI_v4` | 0주 / 6주 벡 불안척도 총점 |
| `나이` | 만 나이 |
| `성별` | 1 = 남, 2 = 여 |

[ 6-2. 어떻게 만들었는가 ]

실제 코호트에서 가져온 것은 지표 16개의 평균과 표준편차 두 숫자뿐임.
개인 값은 전혀 쓰지 않았음.

생성 규칙임.

- 사람마다 고유 수준을 표준정규분포에서 먼저 뽑음. 실제 웨어러블 자료는 개인차가 크고 시점 변화는 작기 때문임
- 같은 사람의 네 시점 상관을 0.70 으로 맞춤. 실제 자료에서 관찰된 값임
- 6주 중등도 이상 우울 양성인 사람에게만 여섯 지표에 약한 신호를 넣음
  평일 이동 거리, 총 활동 시간, 깊은 수면 시간, 주말 이동 거리, 수면 효율은 낮아지는 방향
  비렘수면 심박수는 높아지는 방향
  실제 자료에서 확인된 방향과 같게 맞춘 것임
- 자살사고에는 신호를 넣지 않았음. 우연 수준이 나오는 것이 정상임
- 난수 씨앗 0, 양성률 55퍼센트

구성은 다음과 같음.

| 표현형 | 양성 | 음성 |
|---|---|---|
| 중증도 (HAMD_v4 14점 이상) | 60 | 60 |
| 자살사고 (SUI_v4 1점 이상) | 43 | 77 |
| 불안 (BAI_v4 16점 이상) | 66 | 54 |

[ 6-3. 샘플로 돌리면 나오는 값 ]

비정형 120명, 직교다항 P0와 P1, 랜덤 포레스트 기준임.

| 표현형 | AUC | 민감도 | 특이도 |
|---|---|---|---|
| 중증도 | 81.0 | 76.7 | 71.7 |
| 자살사고 | 50.9 | 27.9 | 72.7 |
| 불안 | 63.9 | 71.2 | 50.0 |

기여 상위는 평일 이동 거리, 총 활동 시간, 주말 이동 거리, 깊은 수면 시간, 비렘수면 심박수 순임.
신호를 넣은 지표가 그대로 상위에 올라옴. 4장과 5장의 해석 방법을 눈으로 확인할 수 있음.

자살사고가 50.9 로 우연 수준인 것은 신호를 넣지 않았기 때문임. 코드 오류가 아님.

[ 6-4. 금지사항 ]

샘플 데이터로 나온 숫자는 논문이나 보고서에 인용하면 안 됨.
코드가 도는지 확인하고 해석 방법을 익히는 용도임.
실제 결과는 5장의 표와 `결과/` 폴더에 있음.

## 7. 실험 설계 요약

| 항목 | 내용 |
|---|---|
| 판별 표적 | 6주 HAMD 14점 이상 / 6주 HAMD 제3문항 1점 이상 / 6주 BAI 16점 이상 |
| 모형 | 로지스틱 회귀, 랜덤 포레스트, 그래디언트 부스팅, 서포트 벡터 머신 |
| 교차검증 | 정형 5겹 20회 반복(분할 비교) 및 10회 반복(지표), 비정형 5겹 5회 반복 곱하기 씨앗 4개 |
| 판정 임계값 | 0.5 고정 |
| 보고 지표 | 정확도, 민감도, 특이도, PPV, NPV, F1, AUC |
| 결측 처리 | 창 품질 기준으로 거른 뒤 분할 내부 중앙값 대치 |
| 불균형 보정 | class_weight balanced. SMOTE 쓰지 않음 |
| 하이퍼파라미터 | 보수적 고정값. GridSearchCV 쓰지 않음 |

민감도와 재현율은 같은 값임. 한 번만 냄.

SMOTE 와 GridSearchCV 를 쓰지 않는 이유임.
합성 표본이 교차검증 겹을 넘나들면 평가가 낙관적으로 흐름.
표본이 작아 하이퍼파라미터 탐색 자체가 또 다른 과적합 경로가 됨.

`step2_analyze.py` 는 이름을 주면 부분 실행됨. 정형, 비정형, 서브그룹, 불안 네 가지임.

## 8. 반드시 지켜야 할 세 가지

전부 실제로 한 번씩 문제가 되었던 것임.

[ 8-1. 심박변이 저주파수와 고주파수는 다른 파일에 있음 ]

Fitbit 은 심박변이를 두 파일로 나눠 내보냄.

| 파일 | 들어 있는 것 |
|---|---|
| `Daily Heart Rate Variability Summary-*.csv` | RMSSD, 비렘수면 심박수, 엔트로피 |
| `Heart Rate Variability Details-*.csv` | 저주파수 LF, 고주파수 HF. 5분 간격 |

Summary 만 읽으면 16지표 중 2개가 통째로 빔. 실제로 한 번 빠뜨려 열이 56개만 나온 적 있음.
`read_hrv_days` 가 두 파일을 모두 읽고 Details 의 5분 값을 하루 평균으로 접음.

[ 8-2. 6주 관찰 창은 마지막 방문일에서 거꾸로 셈 ]

실제 방문 간격이 계획된 42일에서 벗어난 대상자가 많음.
앞에서부터 세면 관찰 창이 6주 임상 평가 시점과 어긋남. `visit_windows` 를 볼 것.

[ 8-3. 결측 대치와 스케일링은 교차검증 분할 안에서만 함 ]

전체 자료로 먼저 중앙값을 구해 채우면 평가 자료 정보가 학습으로 새어 성능이 높게 나옴.
`make_models` 가 대치와 스케일을 sklearn Pipeline 안에 넣어 두어 겹마다 다시 계산됨.
파이프라인 밖에서 미리 채우면 안 됨.

## 9. 설정과 오류

`config.json` 임.

```
{
  "raw_root":     "원본 Fitbit 폴더 경로",
  "subject_xlsx": "대상자 명부 엑셀 경로",
  "out_dir":      "가공된 표를 둘 폴더"
}
```

샘플 데이터로 전체 실험을 돌리려면 `out_dir` 을 `./샘플데이터` 로 바꾸고,
`step2_analyze.py` 안의 `DIR_TWO` 와 `DIR_LONG` 이 가리키는 폴더 이름을
`정형_120명` 과 `비정형_120명` 으로 맞추면 됨.

명부의 방문일이 잘못 적혀 있거나 비어 있으면 원본 엑셀을 고치지 않고
같은 폴더의 `날짜보정.csv` 에 적어 둠. 1단계가 읽어 덮어씀.
원본 엑셀은 연구간호사가 관리하는 자료이기 때문임.

자주 나는 오류임.

| 증상 | 원인과 해결 |
|---|---|
| `FileNotFoundError` | 코드 폴더 안에서 실행해야 함. 경로가 상대 경로임 |
| 1단계에서 대상자 0명 | 원본 폴더에 접근할 수 없음. 2단계부터 실행할 것 |
| 한글이 네모로 나옴 | `biomarker.use_korean_font()` 에 폰트 경로를 넣을 것 |
| `joblib` 임시폴더 오류 | `C:/jltmp` 폴더를 만들 것 |
| SHAP 계산이 느림 | `shap_importance` 의 `n_repeats` 를 줄일 것. 기본 3임 |
