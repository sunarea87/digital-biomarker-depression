# 우울증 디지털 바이오마커 — 시계열 표현 학습 코드

손목 착용형 기기로 6주간 네 번 측정한 수면·심박변이·활동 지표에서
**6주 시점의 우울 중증도를 판별**하는 코드입니다.

핵심 물음은 성능 자체가 아니라 **표현**입니다.
한 사람을 6주간 네 번 관찰했을 때 그 네 점을 어떤 형태로 모형에 넣어야 하는가.

> **데이터는 포함되어 있지 않습니다.** 환자 개인정보가 담긴 원자료는 저장소에
> 올리지 않으며, 경로만 `config.json`으로 지정합니다.

---

## 1. 빠르게 시작하기

```bash
pip install -r requirements.txt
cp config.example.json config.json    # 경로를 본인 환경에 맞게 수정
python preprocess.py                   # 원자료 → 분석용 표
python train.py --task basis           # 표현 비교
python evaluate.py                     # 최종 성능표와 그림
```

---

## 2. 파일 구성

네 개뿐입니다. 기능은 전부 `core.py`에 있고, 나머지 셋은 그걸 불러 쓰는
실행 스크립트입니다.

| 파일 | 하는 일 |
|---|---|
| **`core.py`** | 모든 함수. 원자료 파싱, 특징 생성, 모형, 교차검증, 지표, SHAP, 그림 |
| **`preprocess.py`** | Fitbit 원자료 → 일 단위 표 → 방문 요약표 → 코호트 확정 |
| **`train.py`** | 표현 방식 비교. 제거 실험, 기저 차수 실험, 누출 측정 |
| **`evaluate.py`** | 최종 표현으로 성능표·ROC·중요도 그림 생성 |

`core.py`는 일곱 구역으로 나뉩니다.

1. 설정과 상수 — 지표 목록, 방문 정의, 직교 다항 대비
2. 원자료 파싱 — Fitbit JSON/CSV를 날짜별로 정리
3. 특징 생성 — 방문 요약, 궤적 요약, 다항 기저
4. 모형과 교차검증 — 네 분류기, 환자 단위 분할
5. 지표 계산 — 정확도·민감도·특이도·F1·AUC와 부트스트랩 신뢰구간
6. 해석 — SHAP 중요도
7. 그림 — ROC, 중요도 막대

## 3. 데이터 구조

### 방문 창

6주간 **네 번** 방문하고, 각 방문마다 **7일치**를 씁니다.
연속 42일이 아니라 끊어진 네 구간입니다.

```
0주        2주        4주        6주
[7일]      [7일]      [7일]      [7일]
 ↑ 첫 방문일부터 전진                ↑ 마지막 방문일에서 역산
```

6주 창만 역산하는 이유는, 실제 첫 방문과 마지막 방문 간격이
42일에서 벗어나는 대상자가 절반 가까이 되기 때문입니다.
전진으로만 잡으면 마지막 창이 실제 평가 시점과 어긋납니다.

### 지표 16개

| 모달리티 | 지표 |
|---|---|
| 수면 6개 | 깊은 수면, 얕은 수면, 렘 수면, 수면 중 각성, 수면효율, 침대 체류시간 |
| 심박변이 5개 | 저주파, 고주파, 엔트로피, 비렘수면 심박수, RMSSD |
| 활동 5개 | 평일·주말 이동거리, 평일·주말 소모칼로리, 총 활동시간 |

렘 수면 잠복기는 결측이 많아 제외했습니다.
거리와 칼로리를 평일·주말로 나눈 것은 활동량의 주중 패턴이 다르기 때문입니다.

### 코호트 기준

네 창 **모두**에서 수면·심박변이·활동이 각각 **3일 이상** 있어야 통과합니다
(`core.MIN_DAYS_PER_WINDOW`). 한 창이라도 비면 궤적을 그릴 수 없습니다.

## 4. 표현 방식 — 이 코드의 핵심

같은 자료를 네 가지로 표현해 비교합니다. `core.representation(wide, kind)`.

| 이름 | 구성 | 차원 |
|---|---|---|
| `raw2` | 0주와 6주 원값 | 32 |
| `raw4` | 네 시점 원값 | 64 |
| `traj` | 네 시점 원값 + 궤적 요약(기울기·총변화) | 96 |
| **`poly`** | **직교 다항 P0+P1** | **32** |

### 직교 다항 기저가 무엇인가

네 시점이 등간격이므로 표준 직교 대비로 정확히 분해됩니다.

| 성분 | 대비 | 뜻 |
|---|---|---|
| P0 | `[ 1, 1, 1, 1]` | 6주간 **평균 수준** |
| P1 | `[-3,-1, 1, 3]` | **선형 방향** (좋아지는가 나빠지는가) |
| P2 | `[ 1,-1,-1, 1]` | 곡률 (호전 후 재악화 같은 U자) |
| P3 | `[-1, 3,-3, 1]` | 그 이상 |

지표당 계수 하나씩이므로 P0+P1이면 16×2 = 32차원입니다.

### 실험에서 확인된 것

- **시점을 늘리기만 하면 안 됩니다.** `raw2`(32차원)에서 `raw4`(64차원)로 가면
  선형 모형이 오히려 나빠집니다. 정보가 늘어난 만큼 차원 부담이 커집니다.
- **방향을 뽑아 주면 됩니다.** `poly`는 `raw2`와 같은 32차원인데 트리 모형에서
  6포인트 이상 높습니다.
- **2차 이상은 해롭습니다.** P2를 넣으면 선형 모형이 무너지고, P3까지 넣으면
  더 나빠집니다. 6주 안에 곡률을 추정할 만한 신호가 없다는 뜻입니다.
- **최대 인접변화는 기여가 없습니다.** 궤적 요약 세 가지 중 기울기와 총변화만
  일을 하고, 국소 변동성은 잡음으로 들어갑니다.

`python train.py --task basis` 와 `--task ablation` 으로 재현할 수 있습니다.

## 5. 평가 설계에서 조심한 것

### 한 사람은 한 표본

같은 대상자의 여러 방문을 독립 표본처럼 다루면 성능이 부풀려집니다.
모형이 질병이 아니라 **사람을 알아보기** 때문입니다.
웨어러블 지표는 개인차가 커서, 한 사람의 0주 기록으로 학습하면
같은 사람의 6주 기록을 쉽게 맞힙니다.

이 코드는 `core.cross_val_predict_patient()`로 한 대상자를 하나의 행으로
고정합니다. `python train.py --task leakage` 를 돌리면 방문 단위 분할과
환자 단위 분할의 차이를 직접 잴 수 있습니다.

### 대치와 스케일은 파이프라인 안에서

결측 대치와 최소최대 스케일을 `Pipeline` 안에 넣었습니다.
전체 자료로 먼저 대치하면 평가 겹의 분포가 학습에 새어 들어갑니다.

### SHAP도 평가 겹에서만

`core.shap_importance()`는 학습 겹에서 적합한 모형으로 **평가 겹의**
기여도만 모읍니다. 같은 자료로 적합하고 해석하면 낙관적으로 나옵니다.

### 시드를 여러 개 씁니다

n이 100 내외면 분할 하나의 결과는 흔들립니다.
`--seeds` 로 여러 시드를 주면 평균과 함께 최소·최대가 나옵니다.
시드마다 부호가 바뀌는 이득은 믿을 수 없습니다.

## 6. 설정

`config.example.json`을 복사해 `config.json`으로 쓰십시오.

```json
{
  "raw_root":     "D:/원본데이터",
  "subject_xlsx": "D:/피험자 DATA.xlsx",
  "work_dir":     "./work"
}
```

환경변수로도 줄 수 있습니다: `DBD_RAW_ROOT`, `DBD_SUBJECT_XLSX`, `DBD_WORK_DIR`.

`raw_root` 아래는 Fitbit 내보내기 구조를 그대로 두면 됩니다.

```
raw_root/
  DGT-001/
    Takeout/Fitbit/Global Export Data/     sleep-*.json, distance-*.json, ...
    Takeout/Fitbit/Heart Rate Variability/ Daily Heart Rate Variability Summary*.csv
```

`Fitbit/` 바로 아래에 있는 형태도 자동으로 인식합니다.
