# 우울증 디지털 바이오마커 학습 코드

스마트워치가 기록한 잠, 심장박동, 움직임을 가지고
**6주 뒤에 우울증이 얼마나 심할지 맞히는** 코드입니다.

## 한 줄로 말하면

6주 동안 네 번 측정한 기록을 **어떤 모양으로 정리해야** 컴퓨터가 잘 맞히는지 알아본 코드입니다.

> 환자분들의 실제 데이터는 이 저장소에 들어 있지 않습니다.
> 데이터가 있는 위치만 설정 파일에 적어두고 씁니다.

<br>

## 1. 무엇을 하는 연구인가요

우울증 환자분들이 손목에 스마트워치를 차고 6주를 지냅니다.
그동안 시계는 이런 것들을 자동으로 기록합니다.

* 어젯밤에 얼마나 깊게 잤는지
* 심장이 얼마나 규칙적으로 뛰는지
* 하루에 얼마나 걸었는지

그리고 6주째에 의사 선생님이 우울증 점수를 매깁니다.

**우리가 궁금한 것은 이겁니다.**
시계 기록만 보고도 6주 뒤 점수를 미리 알 수 있을까요?

<br>

## 2. 데이터가 어떻게 생겼나요

### 네 번 측정합니다

병원에 네 번 옵니다. 0주, 2주, 4주, 6주입니다.
올 때마다 **그 주변 7일치** 기록을 씁니다.

```
   0주          2주          4주          6주
 [7일치]      [7일치]      [7일치]      [7일치]
```

6주 내내 계속 기록한 것이 아니라, **띄엄띄엄 네 덩어리**입니다.

한 가지 주의할 점이 있습니다.
0주, 2주, 4주는 첫 방문 날짜부터 세어 나가는데,
**6주만 마지막 방문 날짜에서 거꾸로 셉니다.**
사람마다 마지막 방문이 정확히 42일째가 아니기 때문입니다.
어떤 분은 40일, 어떤 분은 45일에 오셨습니다.

### 지표는 16개입니다

| 종류 | 무엇을 재나요 | 개수 |
|------|--------------|------|
| 잠 | 깊은 잠, 얕은 잠, 꿈꾸는 잠, 자다 깬 시간, 잠의 효율, 침대에 누워 있은 시간 | 6개 |
| 심장 | 심장 박동의 규칙성 관련 5가지 | 5개 |
| 활동 | 평일과 주말의 걸은 거리, 평일과 주말의 소모 칼로리, 총 활동 시간 | 5개 |

걸은 거리와 칼로리를 평일과 주말로 나눈 이유가 있습니다.
사람은 평일과 주말에 활동량이 다르기 때문입니다.
주말에만 많이 걷는 분과 매일 비슷하게 걷는 분은 다른 사람입니다.

### 기록이 너무 적으면 제외합니다

네 번 모두에서 잠, 심장, 활동이 **각각 3일 이상** 있어야 분석에 씁니다.
한 번이라도 기록이 비면 변화를 그릴 수 없기 때문입니다.

<br>

## 3. 이 코드의 핵심 질문

한 사람한테 숫자가 **16개 지표 곱하기 4번 = 64개** 나옵니다.
이걸 컴퓨터에 어떻게 넣어야 할까요?

네 가지 방법을 비교했습니다.

| 이름 | 방법 | 숫자 개수 |
|------|------|----------|
| `raw2` | 처음과 마지막, 두 번만 넣기 | 32개 |
| `raw4` | 네 번 다 넣기 | 64개 |
| `traj` | 네 번 다 넣고, 변화량도 계산해서 추가 | 96개 |
| **`poly`** | **평균과 기울기만 계산해서 넣기** | **32개** |

### poly 가 무슨 뜻인가요

지표 하나를 놓고 보겠습니다. 예를 들어 깊은 잠 시간이요.

```
0주: 40분    2주: 45분    4주: 50분    6주: 55분
```

이 네 숫자를 그대로 넣는 대신, 두 가지만 뽑습니다.

* **평균**: 6주 동안 평균 몇 분 잤나요? (47.5분)
* **기울기**: 늘고 있나요 줄고 있나요? (늘고 있음, 2주에 5분씩)

이 두 개면 충분하더라, 라는 것이 이 연구의 결론입니다.

<br>

## 4. 알아낸 것

### 시간을 많이 재는 것만으로는 부족합니다

네 번 다 넣으면 두 번만 넣는 것보다 오히려 **나빠지는** 경우가 있었습니다.
숫자가 많아진 만큼 컴퓨터가 헷갈렸기 때문입니다.

### 대신 "어느 방향으로 가고 있나"를 알려주면 좋아집니다

숫자 개수는 두 번 넣을 때(32개)와 똑같은데,
평균과 기울기로 바꿔 넣으니 **정답률이 6점 넘게 올랐습니다.**

### 너무 복잡하게 만들면 다시 나빠집니다

기울기보다 더 복잡한 것도 넣어봤습니다.
"좋아졌다가 다시 나빠지는 U자 모양"을 잡아내는 계산인데요,
**넣으니까 오히려 성적이 떨어졌습니다.**

6주는 그런 복잡한 모양을 찾아내기에 너무 짧은 기간인 것 같습니다.

### 쓸모없는 계산도 있었습니다

"측정할 때마다 얼마나 널뛰었나"도 계산해봤는데, 전혀 도움이 안 됐습니다.
그냥 방해만 됐습니다.

직접 확인해보시려면 이렇게 하세요.

```bash
python train.py --task basis        # 복잡하게 만들면 나빠지는 것 확인
python train.py --task ablation     # 쓸모없는 계산 찾아내기
```

## 5. 조심한 것들

### 한 사람은 한 줄로만

이게 가장 중요합니다.

같은 사람의 0주 기록과 6주 기록을 **다른 사람인 척** 넣으면 안 됩니다.
성적이 실제보다 훨씬 좋게 나오는데, 이유가 있습니다.

컴퓨터가 **병을 알아본 게 아니라 사람을 알아본 것**이기 때문입니다.

사람마다 잠버릇이나 심장 박동이 꽤 다릅니다.
그래서 김철수씨의 0주 기록으로 공부한 컴퓨터는
김철수씨의 6주 기록을 보면 "아, 아까 그 사람이네" 하고 알아챕니다.
병을 맞힌 게 아니라 사람을 맞힌 겁니다.

이 코드는 **한 사람을 반드시 한 줄로만** 넣습니다.

얼마나 차이 나는지 직접 재보실 수 있습니다.

```bash
python train.py --task leakage
```

### 빈칸 채우기는 공부할 때만

기록이 빠진 곳은 다른 값으로 채워야 하는데,
**시험지를 보고 채우면 안 됩니다.**
공부용 자료만 가지고 채웁니다.

### 중요한 지표 찾기도 시험지에서만

어떤 지표가 중요했는지 계산할 때도,
공부한 자료 말고 **시험 본 자료에서만** 계산합니다.
그래야 정직한 결과가 나옵니다.

### 여러 번 섞어서 해봅니다

사람이 100명 정도라 적습니다.
한 번만 해보면 운이 좋아서 잘 나올 수도 있습니다.
그래서 **자료를 여러 방식으로 섞어가며** 반복합니다.
섞을 때마다 결과가 뒤집히면 믿을 수 없는 결과입니다.

## 6. 파일이 4개뿐입니다

| 파일 | 하는 일 |
|------|---------|
| **`core.py`** | 모든 기능이 여기 있습니다. 나머지는 여기서 꺼내 씁니다 |
| **`preprocess.py`** | 시계 기록을 표로 정리합니다 |
| **`train.py`** | 어떤 방법이 좋은지 비교합니다 |
| **`evaluate.py`** | 최종 성적표와 그림을 만듭니다 |
| `make_demo_data.py` | 데이터 없이 돌려볼 수 있게 가짜 데이터를 만듭니다 |

`core.py` 안은 일곱 칸으로 나뉘어 있습니다.

1. 기본 설정 (지표 이름, 방문 날짜 규칙)
2. 시계 기록 읽기
3. 숫자 만들기 (평균, 기울기)
4. 컴퓨터 학습시키기
5. 성적 매기기
6. 중요한 지표 찾기
7. 그림 그리기

<br>

## 7. 실행 방법

```bash
pip install -r requirements.txt

cp config.example.json config.json
# config.json 을 열어서 데이터 위치를 적으세요

python preprocess.py     # 1단계: 기록을 표로 정리
python train.py          # 2단계: 방법 비교
python evaluate.py       # 3단계: 성적표와 그림
```

### 설정 파일은 이렇게 생겼습니다

```json
{
  "raw_root": "D:/원본데이터",
  "subject_xlsx": "D:/피험자 DATA.xlsx",
  "work_dir": "./work"
}
```

* `raw_root`: 시계에서 내려받은 파일들이 있는 폴더
* `subject_xlsx`: 환자분 정보와 우울증 점수가 있는 엑셀
* `work_dir`: 결과물이 저장될 폴더

### 원본 데이터 폴더는 이렇게 생겼습니다

```
원본데이터/
  DGT-001/
    Takeout/Fitbit/Global Export Data/      잠, 걸음 기록
    Takeout/Fitbit/Heart Rate Variability/  심장 기록
  DGT-002/
    ...
```

Fitbit에서 내려받은 그대로 두시면 됩니다.

## 7-1. 데이터 없이 먼저 돌려보기

환자 데이터를 아직 못 받으셨어도 코드가 어떻게 도는지 볼 수 있습니다.
가짜 환자 데이터를 만들어주는 프로그램이 들어 있습니다.

```bash
python make_demo_data.py
python train.py --config demo_config.json --task basis
python evaluate.py --config demo_config.json
```

### 이 데이터는 무엇인가요

**전부 컴퓨터가 지어낸 숫자입니다.**
실제 환자분의 기록은 한 줄도 들어 있지 않습니다.

실제 데이터에서 가져온 것은 딱 두 가지뿐입니다.

* 지표별 **평균** (예: 깊은 잠은 평균 51.7분)
* 지표별 **퍼짐 정도** (예: 표준편차 21.2분)

이 두 숫자는 개인을 알아볼 수 없는 요약값입니다.
여기에 난수를 섞어 가짜 사람 120명을 만듭니다.

### 왜 진짜처럼 만들었나요

아무 숫자나 넣으면 코드가 돌아가긴 해도
**결과가 실제와 너무 달라서** 참고가 안 됩니다.
그래서 실제 데이터의 세 가지 성질을 흉내 냈습니다.

| 성질 | 어떻게 만들었나 |
|------|----------------|
| 사람마다 많이 다르다 | 먼저 사람별 기본값을 뽑고, 그 위에 시점별 흔들림을 얹습니다 |
| 같은 사람의 네 시점은 닮았다 | 시점 간 상관을 0.70으로 맞췄습니다. 실제 값과 같습니다 |
| 우울이 심하면 덜 움직인다 | 정답이 1인 사람은 활동량과 깊은 잠을 조금 낮게 만듭니다 |

### 왜 120명인가요

처음에는 10명으로 만들었는데 **결과가 엉망으로 나왔습니다.**
자료를 다섯 조각으로 나눠 시험을 보는데,
10명이면 한 조각에 2명뿐이라 점수가 의미를 잃습니다.

실제 코호트와 비슷한 120명으로 맞추니 제대로 작동합니다.
인원을 바꾸고 싶으면 이렇게 하세요.

```bash
python make_demo_data.py --n 60
```

30명 아래로 내리면 결과가 크게 흔들립니다.

### 예제로 돌리면 이런 결과가 나옵니다

```
모형             LR    RF   SVM   XGB
P0 평균만       81.5  78.5  81.1  75.5
P0+P1 평균·선형  84.9  79.7  85.6  77.5      <- 가장 좋음
P0..P2 +2차   81.4  77.1  80.0  73.9
원값 2시점       81.2  79.4  81.6  78.0
원값 4시점       80.9  77.8  82.2  74.5
```

평균과 기울기만 넣은 `P0+P1` 이 가장 좋다는 것이 보입니다.
실제 데이터에서도 같은 순서가 나옵니다.

다만 **점수 자체는 실제와 다릅니다.**
가짜 데이터라 신호를 일부러 넣어둔 것이라서,
예제 점수가 실제 성능이라고 생각하시면 안 됩니다.

### 만들어지는 파일

```
demo_data/
  visit_wide.csv   120명 x 64열 (16지표 x 4시점)
  cohort.csv       120명의 정답 (6주에 중등도 이상인가)
```

## 10. 아쉬운 점

**관찰 기간이 짧습니다.**
한 사람당 28일치입니다. 다른 연구들은 400일 넘게 보기도 합니다.
그런 연구에서는 생체 리듬 같은 것도 계산할 수 있는데, 우리는 못 합니다.

**어떤 방법에서는 효과가 작습니다.**
평균과 기울기로 바꾸면 대부분 좋아지지만,
방법에 따라 좋아지는 폭이 다릅니다.

**병원 한 곳에서만 모았습니다.**
다른 병원 환자분들에게도 통할지는 아직 모릅니다.

**마지막 6주째 기록이 가장 많이 빕니다.**
시간이 지나면서 시계를 안 차시는 분들이 생기기 때문입니다.
분석에서 빠지는 분들의 절반 이상이 6주째 기록 부족 때문입니다.
